## 一、优势与特长

1. **深耕工业软件与机器视觉交叉方向**：熟悉工业相机成像链路与上位机软件开发全流程，能独立完成从相机 SDK 接入、图像采集、参数建模到界面呈现的完整技术闭环。
2. **架构意识强，注重可扩展性**：习惯在动手前先划分抽象边界，项目核心诉求是"换相机品牌不改上层代码"，具备用设计模式解决真实工程痛点的落地经验。
3. **自驱型开发习惯**：长期独立承担项目从需求分析、架构设计、编码实现到联调测试的全部环节，无人带教情况下完成过多轮从 0 到 1 的功能迭代。
4. **重视工程质量与可维护性**：坚持分层解耦、资源可控、异常可兜底，代码结构清晰，具备工控软件长期运行所需的稳定性意识。
5. **学习与迁移能力强**：可快速吃透第三方 SDK 与协议文档，能把陌生的硬件接口抽象成稳定的上层契约。

## 二、专业技能

- **设计模式**：单例、工厂、抽象工厂、适配器、观察者、策略、模板方法、原型、生产者-消费者、模型-视图-委托（MVD）。

- **开发工具**：CMake（AUTOMOC/AUTORCC、多配置构建）、MSVC / GCC、Visual Studio、Git、Qt Creator。
- **通信与协议**：GenICam / SFNC、GigE Vision、USB3 Vision、Modbus / TCP（了解）。
- **系统与平台**：Windows、跨平台（Linux）构建与部署，进程/线程模型，中文编码与本地化处理。

## 三、项目经历

### ZyClear —— 跨品牌兼容的工业相机客户端软件

**个人独立开发 ｜ C++17 / Qt 6 / OpenCV 4.5 / 海康 MVS SDK ｜ 2024.xx – 至今**

**项目描述：**
一款面向工业视觉现场的相机客户端上位机，功能对标海康官方 MVS，覆盖"相机枚举 → 连接控制 → 参数配置 → 实时预览 → 配置持久化"的完整设备管理链路。项目最大的设计目标不是"做出一个能用的界面"，而是解决同类软件长期存在的两个结构性问题：其一，换一家相机厂商就要改动上层业务代码；其二，每新增一个相机型号就要手写一套参数面板适配代码。为此在架构上抽象出设备接口层、统一参数模型与数据驱动的界面框架，使新品牌接入与新型号适配都退化为"纯新增"操作。

**核心技术与实现：**

- **设备无关的分层架构**：按"表现层 / 门面层 / 抽象接口层 / 设备实现层 / 支撑层"五层组织代码。定义纯虚接口 `CameraInterface` 作为相机操作契约（连接、取流、参数读写、事件回调），业务侧的 `CameraContext` 门面单例只面向接口编程，对上层界面完全屏蔽具体品牌实现，落地依赖倒置。

- **工厂模式实现品牌热接入**：`CameraFactory` 单例维护"产品名 → 创建函数"的注册表，采用 `std::function` + lambda 的模板注册方式，把构造逻辑与工厂本体解耦。接入新品牌时只需实现接口并追加一行注册，不在任何既有文件中修改判断分支，是开闭原则与"零修改、纯新增"的具体落地。

- **适配器封装海康 SDK 全生命周期**：将海康 `MvCameraControl` C 接口封装为符合项目契约的实现类，内部串联 `MV_CC_EnumDevices`（GigE + USB 双协议枚举）→ `CreateHandle` → `OpenDevice` → 注册图像回调 → 设置取流策略（OneByOne）与缓存节点数 → `StartGrabbing` 的完整流程；参数读写按类型分发到 `MV_CC_Get/Set Int/Float/Enum/Bool/String/Command`，并借 `MV_XML_GetNodeAccessMode` 解析节点读写权限，只读参数自动置灰、命令型参数渲染为触发按钮。

- **统一参数模型屏蔽 SDK 差异**：抽象组合式结构体 `CameraParam`，把不同厂商名称各异的参数统一为"名称 + 类型 + 取值域 + 分组 + 描述 + 访问权限位（valid / readable / writeable）"的自描述模型，值以 `QVariant` 承载六种类型并注册为 Qt 元类型。参数层、界面层、SDK 层三方据此解耦，上层不再感知任何厂商字段命名。

- **生产者-消费者图像队列**：自实现线程安全队列 `CameraImageQueue`，采用空闲队列 + 工作队列的双队列结构，配合 `std::mutex` 与 `std::condition_variable` 完成阻塞取图。图像缓冲区在初始化阶段一次性预分配并循环复用，采集过程不产生新的堆分配；等待采用 5 秒超时机制，队列满时以覆盖最旧帧的方式保证实时性优先，避免因界面卡顿拖垮采集线程。

- **三线程协同的采集链路**：SDK 回调线程负责收图入队，独立采集线程负责出队并做像素格式转换（Mono / Color → Mono8 / RGB8），GUI 线程只做渲染。三层之间通过线程安全队列与跨线程信号槽解耦，任何一环抖动都不会阻塞界面；配合 `ImageConver` 中基于 `mat.data` 的零拷贝构造，省去图像在 OpenCV 与 Qt 之间的整帧复制开销。

- **MVD 架构的参数面板与类型化控件族**：基于 Qt Model-View-Delegate 实现参数面板，`CameraParamModel` 按 group 分组建树、`CameraParamDelegate` 负责编辑器创建与自绘，并为六种参数类型派生 `OneCustomWidget` 控件族（int / double / bool / enum / string / cmd），以策略模式分发编辑行为；新增一种参数类型只需增加一个控件，无需改动模型与视图。

- **JSON 数据驱动界面生成**：设计 `ParseUiJson` 单例解析器，用 JSON 描述参数元信息，运行时反序列化后直接构建参数模型，并内置字段合法性校验与进度、完成信号。实际面板的 5 个分组、37 个参数全部由一份 JSON 驱动，新增相机型号只写配置、不重编译，同时同一份 JSON 也可驱动虚拟相机，实现界面与代码解耦。

- **观察者模式中央事件总线**：自实现 `ListenerManager`，以位掩码标识事件类型，控制面板、参数面板、视觉窗口三大模块通过订阅事件完成状态联动（如连接成功自动加载参数、开始取流禁用相关配置项）。模块之间不持有彼此引用，新增界面模块只需继承 `Listener` 接入，避免界面间形成网状耦合。

- **虚拟相机支撑无硬件开发**：`VirtualCamera` 作为接口的另一种实现，脱离真实硬件即可跑通"枚举 → 连接 → 取流 → 参数读写 → 预览"全链路，以固定节奏生成测试图像并用内置 JSON 参数表返回样例值。真机与虚拟设备共用同一套上层逻辑，开发与自动化回归测试不再依赖硬件到位。

- **专业级图像交互与暗色主题工程化**：基于 `QGraphicsView` 封装视觉窗口，实现滚轮缩放、拖动平移、双击居中、自适应显示与鼠标悬停实时像素取色；界面统一为 VS Code 风格深色主题，`QPalette` 调色板与 QSS 样式表结合；工程侧用 CMake 管理构建，开启 AUTOMOC / AUTORCC，支持多配置与跨平台，并处理 MSVC 下的 UTF-8 中文编码问题。

**项目成果：**

- 独立完成覆盖抽象层、工厂、事件总线、参数面板、图像队列、渲染窗口的完整客户端软件，代码分层清晰、职责单一，具备企业级工业软件的结构形态。
- 架构上实现三项"零成本"扩展能力：新增相机品牌零修改既有代码、新增相机型号零代码、新增参数类型纯新增控件，明显优于同类硬编码方案的维护效率。
- 图像显示在真实取流下稳定流畅，界面操作无卡顿；虚拟相机机制将开发与测试从硬件依赖中解放出来。
- 相比官方 MVS，本软件在多品牌支持、参数面板数据驱动、虚拟调试设备、跨平台能力与开源可扩展性上均有结构性优势。

**技术复用性：**

项目的抽象接口层、工厂注册机制、统一参数模型与生产者-消费者图像队列均为通用组件，可直接迁移到其他工业设备上位机（运动控制卡、PLC、光源控制器等）——把"相机"替换为任意设备类型即可复用同一套分层与解耦思路；JSON 驱动界面的方案亦可复用于任何需要批量参数配置的工控场景。

## 精简版

### ZyClear —— 跨品牌兼容工业相机客户端软件 ｜ 个人独立开发
**C++17 / Qt 6 / OpenCV 4.5 / 海康 MVS SDK**

- 独立开发对标海康 MVS 的工业相机上位机，覆盖枚举、连接、实时采图、参数读写、配置导入导出的完整链路。
- 抽象 `CameraInterface` 设备接口 + `CameraContext` 门面单例，业务层依赖抽象而非实现；`CameraFactory` 以 `std::function` 模板注册实现品牌热接入，新增品牌"零修改、纯新增"。
- 海康 SDK 以适配器封装，贯通枚举、句柄创建、回调取流、六类参数读写与 `.mfs` 配置持久化；`VirtualCamera` 虚拟实现支持脱离硬件调试。
- 自实现双队列 + 条件变量的生产者-消费者图像队列，缓冲区预分配复用，SDK 回调线程与采集线程解耦，界面稳定流畅无卡顿。
- 基于 Qt MVD 构建参数面板，`CameraParamModel` 分组建树、`CameraParamDelegate` + 六类类型化控件；参数以 `QVariant` 统一建模，屏蔽多厂商字段差异。
- 自实现 `ListenerManager` 位掩码事件总线解耦三大界面模块；`ParseUiJson` 以一份 JSON 驱动 5 分组 37 参数，新增型号零代码。
- `QGraphicsView` 实现缩放/平移/取色等专业交互；深色主题 QSS 全量重构；CMake 多配置、跨平台构建。
