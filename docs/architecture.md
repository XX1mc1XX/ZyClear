# 架构说明

本文说明 zyClear 的分层方式、依赖规则与扩展点，以及每条规则的**可验证方法**。
文档中的所有约束都能用 grep 当场核对，不依赖口头承诺。

---

## 一、分层总览

```
┌────────────────────────────────────────────────────────────────┐
│ 资源层   AppStyle（调色板 + QSS）│ Icon │ Resource（参数 Schema）│
└────────────────────────────────────────────────────────────────┘
        ▲ 以 :/ 前缀编译进可执行文件，交互层只按名字引用

┌────────────────────────────────────────────────────────────────┐
│ 交互层   ControlWidget │ ParamWidget │ ViewWidget               │
│          └─ 模型层  CameraParamModel / CameraParamItem / Delegate│
└───────────────────────────────┬────────────────────────────────┘
                                │ 仅凭序列号寻址，不出现任何厂商类型
┌───────────────────────────────▼────────────────────────────────┐
│ 门面层   CameraContext                                          │
│          多机映射 · 生命周期托管 · 当前会话状态                  │
└───────────────────────────────┬────────────────────────────────┘
                                │
┌───────────────────────────────▼────────────────────────────────┐
│ 契约层   CameraInterface（17 个纯虚方法）                        │
│          ZCCameraParam 统一参数模型 │ CameraImageQueue 缓冲队列  │
│          CameraError 统一错误码                                  │
└───────────────────────────────▲────────────────────────────────┘
                                │ 实现契约（依赖倒置）
┌───────────────────────────────┴────────────────────────────────┐
│ 实现层   HikCamera（海康 MVS SDK）│ VirtualCamera（仿真）         │
│          CameraFactory：按厂商名登记「创建器 + 枚举器」          │
└────────────────────────────────────────────────────────────────┘
```

依赖只允许**自上而下**。唯一的反向关系是实现层对契约层的实现（依赖倒置），
因此契约层不需要认识任何一个具体相机。

---

## 二、各层职责

| 层 | 主要文件 | 职责 | 不做什么 |
|---|---|---|---|
| 资源层 | `AppStyle/`、`Icon/`、`Resource/` | 主题样式、图标、参数 Schema | 不含逻辑 |
| 交互层 | `ControlWidget/`、`ParamWidget/`、`ViewWidget/` | 设备列表、参数面板、图像显示 | 不判断厂商、不直接调 SDK |
| 门面层 | `CameraInterface/CameraContext.*` | 序列号寻址、生命周期、会话状态 | 不认识具体适配器 |
| 契约层 | `CameraInterface/` | 定义硬件无关的能力边界与数据模型 | 不依赖 Qt Widgets |
| 实现层 | `CameraFactory/` | 各品牌 SDK 适配、图像格式归一化 | 不接触界面 |

---

## 三、依赖规则的验证方式

这三条是架构的核心约束，任何一条被破坏都应该在评审时被发现：

```bash
# 1. 门面与契约层不得依赖任何具体适配器
grep -rn "HikCamera.h\|VirtualCamera.h" src/CameraInterface/
# 期望：无输出

# 2. 面板之间不得互相持有引用（联动一律走事件总线与门面）
grep -rn "ControlWidget\*" src/ParamWidget/ src/ViewWidget/
# 期望：无输出

# 3. 交互层不得出现厂商名判断
grep -rniE "hikrobot|\"Hik\"|MV_CC_" src/ControlWidget/ src/ParamWidget/ src/ViewWidget/
# 期望：无输出
```

第 1 条带来两个直接收益：**新增品牌不必改动门面**；门面也得以在无 SDK 环境下编译。

## 四、图像链路

采集回调、缓冲队列、采集线程、界面渲染分处四段，任何一段变慢都不会阻塞其余部分。

```
 SDK 回调线程            缓冲队列           采集线程             UI 线程
 ─────────────      ──────────────      ─────────────      ─────────────
 MV_CC 回调
   │ 像素格式归一化（Mono / Bayer / YUV / BGR → Mono8 / RGB8）
   ▼
 HikConvert2Mat
   │ Put()
   ├─ 有空闲缓冲 → 原地 copyTo 复用内存
   └─ 无空闲且队列满 → 丢弃最旧帧，回收其缓冲
   │
   ▼
 工作队列 ──────→ Take() ─→ cvMat2QImage（深拷贝）
                              │
                              ├─ 信号投递 → GraphicsView 渲染
                              └─ Recycle() 归还缓冲 ──┐
                                                       │
 空闲缓冲池 ◄───────────────────────────────────────────┘
```

要点：

- **保新弃旧**：预览关心最新帧，队列满时丢弃最旧帧而非最新帧
- **缓冲循环**：归还动作在消费者完成深拷贝**之后**才发生，保证同一时刻一块缓冲只有一个所有者
- **稳态零分配**：分辨率与像素格式不变时，`copyTo` 原地写入，堆分配只发生在首帧
- **超时保护**：`Take` 带超时，超时回 `GETIAMGE_TIMEOUT`，不会把空帧当作有效图像

对应的单元测试见 `src/tests/test_cameraimagequeue.cpp`。

## 五、参数体系

参数在不同型号间差异极大，因此拆成三段各自独立演进：

```
   参数 Schema (JSON)          解析器              统一模型             界面
   ──────────────────      ─────────────      ──────────────      ─────────────
   group / params      →   ParseUiJson    →   CameraParam     →   MVD 面板
   name / type / tips      逐字段校验          元信息 + 值         按类型挂载控件
                          错误定位到参数        + 访问权限位域
```

- **Schema**：描述有哪些参数、属于哪个分组、什么类型、提示文案
- **统一模型**：`CameraParam` 把六种参数类型压成一个外观类，上层只认 `displayText()` 与三个权限标志
- **权限闭环**：设备的 GenICam 访问模式（`RO` / `RW` / `WO` / `NI` / `NA`）在适配器内被翻译成
  「有效 / 可读 / 可写」三态，界面据此决定单元格能否编辑。参数面板里没有任何硬编码的权限判断。
- **界面**：`CameraParamDelegate` 依据类型在运行时挂载对应编辑控件，界面层对参数数量无感知

对应的单元测试见 `src/tests/test_parseuijson.cpp` 与 `src/tests/test_cameraparam.cpp`。

## 六、扩展点

### 新增一个相机品牌

1. 新建适配器，继承 `CameraInterface`，实现 17 个纯虚方法（含静态的设备枚举函数）
2. 在 `CameraFactory::instance()` 里追加一行 `registerVendor<YourCamera>("厂商名")`
3. 若该 SDK 为可选依赖，仿照海康的做法在 `src/CMakeLists.txt` 里加条件编译

第 1 步之外，门面、参数面板、图像链路**一行都不用改**——这是分层的直接结果。

### 新增一个相机型号

只改 `src/Resource/VirtualCameraParam.json`（或该型号的 Schema 文件），
增删分组与参数即可，**不编译、不发版**。

### 让参数面板支持一种新控件

在 `ParamWidget/CustomWidget/` 下新增一个 `OneCustomWidget` 子类，
基类固定初始化流程，子类只补编辑区，再在 Delegate 的分派处登记。

## 七、构建期能力

`src/CMakeLists.txt` 集中声明了源码清单、资源、依赖与产物路径：

- **可选依赖**：海康 SDK 缺失时不参与编译，工厂也不注册该品牌，程序退化为纯虚拟相机形态仍可构建
- **依赖探测双路径**：OpenCV 先走官方 Config 包，找不到再回退到手工指定头文件与库
- **配置自动二选一**：Debug 链 `opencv_world455d`，Release 链 `opencv_world455`
- **产物集中落盘**：无论 Debug / Release 都输出到 `bin/`，与测试产物同目录，运行时 DLL 齐备

构建与运行方式见 [README](../README.md)。
